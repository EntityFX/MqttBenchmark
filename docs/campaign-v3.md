# Reproducible campaigns (schema v3)

`config/benchmark-campaign.v3.json` defines the 288-key baseline: four brokers × two exact payload sizes (16/256 bytes) × three QoS levels × four publisher counts (1/16/64/128) × three repeats. Each run connects N publishers and one subscriber. Warmup is 5 s, measurement 30 s, cooldown 5 s, with a 30 s drain limit and a 2 s quiet period. Seed 20260909 orders brokers and then their keys by SHA-256; input array ordering and .NET random-number implementation do not affect that order.

Run the CLI from this repository with a clean tracked source tree. The original v2 commands remain available for v2 configurations. V3 outputs and local stand overrides belong under ignored `artifacts/`, `campaigns/`, `results/raw/v3/`, or `config/*.local.json`.

```powershell
dotnet run --project src/EntityFX.MqttBenchmark.Cli -- preflight --stand config/broker-stand.local.json --config config/benchmark-campaign.v3.json --output artifacts/preflight-001
dotnet run --project src/EntityFX.MqttBenchmark.Cli -- matrix --stand config/broker-stand.local.json --config config/benchmark-campaign.v3.json --campaign campaigns/baseline-001
dotnet run --project src/EntityFX.MqttBenchmark.Cli -- matrix --stand config/broker-stand.local.json --config config/benchmark-campaign.v3.json --campaign campaigns/baseline-001 --resume
dotnet run --project src/EntityFX.MqttBenchmark.Cli -- aggregate --config config/benchmark-campaign.v3.json --raw campaigns/baseline-001 --output artifacts/aggregate-001
```

`--docker-executable <path>` selects a Docker CLI that is not on PATH. The stand's Docker context controls the target host. `--benchmark-repo` and `--stand-script` select explicit source/controller paths. `--broker Mosquitto` restricts a preflight or matrix invocation; `--max-runs 1` limits new successful keys, and `--dry-run` lists the selected count without deploying. A short pilot can use an ignored copy of the campaign config with shorter durations; all 288 dimensions remain required. A partial pilot cannot be aggregated. Do not use the unrelated bare-metal port 9883 as a managed stand endpoint.

The CLI delegates source-inventory validation, immutable image/build verification, exclusive broker selection, host networking, CPU/memory settings, health checks, versions and telemetry to `scripts/BrokerStand.ps1`. It first validates the source inventory through that controller, then selects one broker in a new inventory snapshot. A source custom broker may require a cached image build during that validation. Each attempt has its own build/start/capture artifacts. A context file lease prevents concurrent v3 invocations from manipulating the same Docker context. Stand operations performed manually outside this CLI do not participate in that lease.

Preflight performs a separate CONNECT, SUBSCRIBE at the requested QoS, PUBLISH, and matching loopback delivery for QoS 0, 1 and 2. It measures 20 MQTT QoS0 echo RTTs and uses their median as `rttBaselineMs`. It subscribes to `$SYS/broker/version` for up to 10 s; absent/rejected SYS output stays `null`/`unavailable` with the error recorded. Executable version output from the stand capture is a separate source and never substitutes a SYS value. Environment capture contains OS/runtime/architecture, CPU count and stopwatch frequency, without collecting environment variables. Telemetry manifests name their CPU (`container-cgroup`) and network (`host-shared`) scopes and include hashes of the original capture files. Preflight failures are retained and exit with code 2.

Every attempt writes `started.json`, `publishes.ndjson`, `deliveries.ndjson`, stand/protocol/preflight evidence, `result.json`, and a `sha256.json` seal. New files use exclusive creation; a finalized attempt's files are never reopened for writing. The campaign manifest binds the campaign ID, exact config and stand hashes, deployment/CPU mode and benchmark Git revision. Resume requires the same identity, verifies sealed artifact hashes, skips only successful keys, and counts an interrupted unsealed attempt against the three-attempt limit. A third failure stops the whole campaign, including later resume calls. A corrupt or unrecognizable history fails closed. After cancellation, close the process normally where possible; retained partial bytes are evidence, not a successful result.

Each payload's first 16 bytes are the first 128 bits of SHA-256 over an unambiguous JSON encoding of campaign ID, run/attempt ID, publisher and sequence. This is the recoverable message ID; a 16-byte message consists entirely of that ID. Remaining payload bytes repeat the deterministic hash. Event logs retain IDs, publisher/sequence, sizes, completion/error outcomes, and elapsed times. Warmup has a separate identity/topic and is excluded from measurement.

`actualMeasurementSeconds` is measured with a monotonic clock from publisher-work dispatch until all issued publish operations settle, including in-flight completion beyond the requested cutoff. Attempted and completed RPS divide their respective counts by that observed interval. Publish failure is failed / attempted. Conditional delivery loss is 1 − uniquely delivered completed IDs / completed publishes (zero when no publishes completed). The counters distinguish unique attempted-ID receipts, repeat receipts, unexpected receipts, and unique receipts associated with a publish whose final outcome failed, including a receipt that arrived before the failure was known. Duplicate and unexpected counts are independent diagnostics and may overlap. They never reduce loss below zero.

QoS0 latency is always `null`/`notApplicable`. QoS1/2 latency runs from the call to publish through its full completion, including PUBACK or PUBCOMP. The drain ends when all completed IDs are received, when no delivery has arrived for the quiet period after measurement, or at timeout. Once drain ends, accounting freezes; later delivery is outside the observation window. The sampler covers the configured warmup/measurement/drain/cooldown envelope plus 20 s for setup/in-flight completion, and the attempt waits for capture before sealing. Raw event logging and retaining message IDs consume client CPU, disk and memory; the client must be sized and observed accordingly for a full baseline.

Aggregation verifies 288/288 unique successful keys and rejects mixed campaign, deployment, CPU, source or config identities. `broker-observations.v3.json` contains 96 points, one per broker/payload/QoS/publisher combination. Rate fields contain mean, sample standard deviation, Student-t CI95 (df=2), min, max and count. Observed latency knots are repeat means, with per-knot statistics alongside them; QoS0 knots stay null. `rttBaselineMs` is the mean of the three per-run median RTT baselines. Task 3 can consume `points[].attemptedRps.mean`, `completedRps.mean`, `publishFailureRate.mean`, `deliveryLossRate.mean`, `observedLatencyQuantiles` and `rttBaselineMs`. Processing latency and conditional simulator failure calibration are deliberately computed by MqttY. Three repeats provide limited statistical power; confidence bounds are statistical intervals and are not clamped to the physical rate range.
