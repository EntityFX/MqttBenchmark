## Review fix — sampler lifetime and complete workload coverage

Review correctly identified that an incomplete controller task does not prove the sampler is still running: Docker log collection and config hashes happen after sampling. Two behavioral regressions against the real controller with delayed Docker logs reproduced false success, both before workload dispatch (one-sample capture) and when sampling finished during the workload. Both tests were RED because the old method returned success. A third RED case showed why controller receipt of the end event alone is insufficient: a delayed final sample can predate remote workload completion.

The fix atomically writes `sampler-ended.json` at the final streamed sample, before post-sampler log capture. A one-sample capture publishes its end before readiness, preventing any workload dispatch. Matrix execution checks sampler state at dispatch and completion. It then issues a read-only `fence` action after the workload, reading `/proc/uptime` in the same broker container. The final sample's monotonic timestamp must be strictly greater than that fence, and readiness/end/fence container identities must match. This establishes first-sample-before-work and last-sample-after-work causally without wall-clock assumptions, including delayed event transport. The configured sample count/duration is unchanged; inadequate coverage fails rather than extending the run.

Capture sample collection and manifest sealing are separate. All fence and controller writers finish before coverage validation and manifest hashing. Cancellation, failed sampling and insufficient coverage cannot seal a successful telemetry manifest. The positive test verifies hashes of the finalized fence/end and other capture evidence. The existing matrix identity test now gives its sampler realistic temporal spacing so its intended successful first workload has actual sample coverage.

## Mandatory Windows load-generator guard

The matrix path now starts a separate local guard before workload dispatch and cannot return a successful attempt until its actual measurement is covered and accepted. The runner supplies the same UTC and `Stopwatch.GetTimestamp` bounds used to calculate `actualMeasurementSeconds`, including in-flight publish settling. This does not change the broker observations schema or remote sampler/fence requirements. Stand and local writers finish before journal sealing; threshold failures use the existing three-attempt retry policy.

Production reads whole-system Windows `GetSystemTimes` counters (kernel includes idle) and cumulative RX/TX bytes on the OS-selected broker route. `GetBestInterfaceEx` selects a single interface, not aggregate adapters. Route/interface loss or change, nonpositive/changed capacity, loopback/tunnel, ambiguous DNS and multiple Windows processor groups fail closed. The read-only native smoke successfully discovered `10.10.157.111 -> Ethernet 9`, Intel(R) 82579LM Gigabit Network Connection, interface index **39**, ID `{D8909FF0-176D-4CC5-A372-3F3D376C37ED}`, speed **1,000,000,000 bit/s**, and returned actual system/network counters. This smoke did not connect to MQTT or start a broker/pilot/baseline.

The acceptance rule is deliberately the **maximum overlapping interval**, not a run average. Every interval intersecting the actual measurement must have CPU <=70% and `(RX bits/s + TX bits/s) / link speed <=70%`. This combined-direction rule is conservative on full-duplex Ethernet. Exactly 70% passes; any exceedance fails. Boundary-crossing buckets are assessed in full, not prorated; buckets outside measurement or only touching its boundaries are excluded. Sampling targets one second. More than **1.25 seconds** between bracketed reads fails coverage (250 ms scheduling tolerance). The first complete read must precede measurement and a final read must start after it. Read brackets produce a conservative minimum rate denominator. Counter decrease/reset/wrap, overlapping reads and invalid CPU totals fail rather than inventing deltas. This guards one-second interval averages, not undetectable subsecond peaks.

Exclusive-create local artifacts record reservation/source/machine/OS, interface identity/capacity, all raw counters and UTC/monotonic brackets, exact measurement boundaries, threshold/cadence, interval CPU/RX/TX/network values and assessment failures. Files are named `load-generator-started.json`, `load-generator-provenance.json`, `load-generator-samples.ndjson`, `load-generator-measurement-started.json`, `load-generator-measurement-ended.json`, and `load-generator-summary.json`. Cancellation or incomplete workload stops/awaits sampling, closes the writer and records failed local evidence. Post-workload completion waits at most five seconds for final coverage. There is no CLI bypass; injected counters/clock exist for deterministic tests.
