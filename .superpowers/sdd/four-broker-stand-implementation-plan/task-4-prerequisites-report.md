## Telemetry and clock readiness

`BrokerStand.ps1` streams each remote sampler output line and persists the first complete sample before atomically publishing `telemetry-ready.json`. `StandSession.RunWithTelemetryAsync` admits workload dispatch only after readiness, bounds startup at 60 seconds, rejects completed/failed captures before dispatch or workload completion, cancels/awaits capture on error, and waits for capture before returning success. The matrix command now uses this method. `measurement-started.json` records workload dispatch (including warmup), while observation timing retains the actual measurement interval.

Stand startup now runs a read-only clock action after health. Three `docker exec date -u +%s` probes use the actual selected context and broker container. The clock report retains UTC brackets, monotonic RTTs, offset/uncertainty, method, controller machine and running container/image provenance. The lowest-RTT probe must satisfy `abs(remoteMinusControllerOffsetMs) + uncertaintyMs <= 2000`. Quantization contributes 500 ms after centring the integer second; half RTT and observed wall/monotonic drift are added. Any controller clock step over 100 ms rejects readiness. An unready stand is stopped and the clock evidence remains. No clock setters or credential collection were added. This is a conservative gross-alignment gate, not a claim of subsecond synchronization.
